# 여행 루트 플래너 — 1번 조각 설계

**목적** — 가고 싶은 곳은 있는데 경로를 못 짜는 사람에게, 「N곳을 M일로 어떻게 나누고 하루에 어떤 순서로 도나」를 답해준다.
**출발점** — 2026-10 런던·파리 가족여행에서 쓴 플래너. 거기서 확인된 코어는 *행위가 체류시간을 정한다*(들렀다 ≠ 갔다)는 것이고, 하루 안의 시간 계산기는 그대로 가져온다.
**이번 조각의 경계** — 고정 중요도 + 꼭 가기 표시 + 지리 묶음 + 하루 순서 + 체류 선택지 + 자동 자르기. **운영시간·계정·관심축 필터·호텔/준비물/사진/기념품 탭·태양 그림자는 전부 뒤 조각**이다.

## 전체 조각 순서 (이 문서는 ①만 다룬다)

① 경로 엔진 → ② 계정·여행 저장 → ③ 운영시간·휴관일 레이어 → ④ 주변 탭(호텔·준비물·기념품·사진) → ⑤ 태양·그림자 사진 명당

④의 모든 탭은 ①의 출력(확정 경로)을 입력으로 받는다. ③은 ①의 시간 계산기 위에 하드 제약으로 얹는다.

## 1. 데이터

### 도시 파일 `data/<city>.json`

| 필드 | 타입 | 필수 | 뜻 | 예 |
|---|---|---|---|---|
| `city` | string | ✓ | 파일명과 같은 키 | `london` |
| `name` | string | ✓ | 표시 이름 | `런던` |
| `center` | [lat, lng] | ✓ | 출발점 기본값 · 지도 초기 중심 | `[51.507, -0.128]` |
| `places` | Place[] | ✓ | 아래 | |

### Place

| 필드 | 타입 | 필수 | 뜻 | 예 |
|---|---|---|---|---|
| `id` | string | ✓ | 도시 안 고유, 영문 소문자 | `stpaul` |
| `name` | string | ✓ | 표시 이름 | `세인트폴 대성당` |
| `lat`, `lng` | number | ✓ | WGS84 | `51.5138`, `-0.0984` |
| `weight` | 1 · 2 · 3 | ✓ | 고정 중요도 등급. 1 = 그 도시를 대표 | `1` |
| `opts` | {label, min}[] | ✓ 1개↑ | 행위 → 체류 분. 순서 = 가벼운 것부터 | `[{"밖에서만",30},{"돔까지",105}]` |
| `default` | int | ✓ | `opts` 기본 인덱스 | `0` |
| `note` | string | ✓ | 설명 한두 문단. `<b>`만 허용 | `렌, 1710. 돔이 셋인 이유는…` |
| `q` | string | — | 지도·사진 검색어 (없으면 `name`) | `St Paul's Cathedral London` |

중요도는 **모두에게 같은 고정값**이다. 사람에 따라 달라지는 것(관심축 필터)은 이 조각에서 하지 않는다.
운영시간 필드는 **두지 않는다**. ③에서 `hours` 를 추가한다.

### 사용자 상태 — URL 해시

저장소가 없다. 상태 전부를 해시에 넣어 **링크 복사 = 저장 = 공유**로 쓴다.

| 키 | 뜻 | 형식 | 예 |
|---|---|---|---|
| `c` | 도시 | string | `london` |
| `d` | 일수 | int 1–10 | `3` |
| `t` | 하루 시작 | 자정 기준 분 | `570` (9:30) |
| `e` | 하루 끝 | 자정 기준 분 | `1140` (19:00) |
| `s` | 출발점 | `lat,lng` · 없으면 `center` | `51.486,-0.125` |
| `p` | 고른 장소 | `id:optIdx` 쉼표 | `stpaul:1,borough:1` |
| `m` | 꼭 가기 | id 쉼표 (`p`의 부분집합) | `borough` |
| `u` | 사용자 장소 | `name~lat~lng~min` 파이프 | `이코이~51.512~-0.113~180` |

해시가 없거나 깨지면 1단계 초기 화면. 모든 키는 선택이고 기본값이 있다.

### 이동시간 추정 `travel.js`

라우팅 API 없이 결정적으로 추정한다.

| 직선거리 d | 수단 | 분 |
|---|---|---|
| d ≤ 2.0 km | 도보 | `d × 1.3 / 4.5 × 60` (우회계수 1.3, 4.5 km/h) |
| d > 2.0 km | 지하철 | `15 + d × 1.0` (접근·대기 15분 + km당 1분) |

정확도는 ±10분으로 보고 화면에 「추정」이라 적는다.

## 2. 엔진 `engine.js` — 순수 함수 다섯 단계

**입력** `plan(places, {days, start, dayStart, dayEnd})` — `places`는 사용자가 고른 Place에 `must`(bool)·`opt`(int)를 붙인 것. 사용자 장소도 같은 형태(weight=1, opts 1개).
**출력** `{ days: Day[], dropped: {place, reason}[] }`, `Day = { stops: {place, arrive, depart}[], why: string, walkKm, moveMin }`.

| 단계 | 하는 일 | 규칙 |
|---|---|---|
| 씨앗 | 묶음 M개의 중심을 고른다 | 꼭 가기 중 서로 가장 먼 M개(k-means++ 식). 모자라면 weight 1 → 2 순으로 채운다. 장소가 M보다 적으면 M을 줄인다 |
| 묶기 | 장소를 묶음에 배정 | 가장 가까운 중심에 붙이고 k-means 10바퀴(위경도 평면 근사). 한 묶음의 체류 합이 예산 × 1.2를 넘으면 꼭 가기 아닌 최하 weight를 여유 있는 가장 가까운 묶음으로 넘긴다. 3바퀴 |
| 순서 | 묶음 안 방문 순서 | 7곳 이하: 출발점에서 시작하는 **완전탐색**, 이동 합 최소. 8곳↑: 최근접 + 2-opt |
| 시간 | 도착·출발 시각 | `dayStart`에서 체류·이동을 순서대로 쌓는다. 런던·파리 도구의 `solve()` 와 같은 계산 |
| 자르기 | 예산 초과 해소 | 마지막 출발이 `dayEnd`를 넘기면 그날의 **꼭 가기 아닌 것 중 최하 weight**(동률이면 체류 긴 것)를 빼고 순서·시간을 다시 돈다. 꼭 가기만 남았는데도 넘치면 그대로 두고 경고 |

**결정성** — 동률은 `id` 사전순으로 깬다. 같은 입력이면 항상 같은 출력.
**설명** — 날마다 `why` 한 줄: 반경(`서로 1.2km 안`) 또는 씨앗(`꼭 가기 X 중심`).
**뺀 것** — `dropped[]`에 `reason` (`"3일차가 19:00을 40분 넘겨서"`).

## 3. 화면 — 한 페이지, 세 단계

레이아웃은 런던·파리 도구의 2단(지도 2 : 설명 1)을 그대로 쓰고, 상단 탭이 단계가 된다. 좁은 화면에선 한 단으로 접힌다.

| 단계 | 왼쪽 (지도) | 오른쪽 |
|---|---|---|
| ① 설정 | 도시 타일 중심. 클릭하면 출발점 핀 | 도시 선택(런던/파리), 일수 ±, 시작·끝 시각 ± |
| ② 장소 | 전 장소 마커. 고른 건 강조, 꼭 가기는 테두리. 빈 곳 클릭 → 「내 장소 추가」 | 1·2·3순위로 묶인 목록. 체크 · 「꼭」 토글 · 행위 선택(opts) |
| ③ 결과 | 날짜별 색 선 + 번호 마커. 날짜 레이어 켜고 끄기 | 날짜 패널(정류장·시각·선택지 칩·`why`), 「뺀 것」 상자, 「링크 복사」 |

③에서 칩을 바꾸면 엔진이 즉시 다시 돌고 해시가 갱신된다. 지도는 **Leaflet + OpenStreetMap**(키 없음). 런던·파리 도구의 `render` · 날짜 패널 · 드래그 스크롤 · 줌은 재사용하고, 손그림 SVG 지도만 Leaflet으로 바뀐다.

```
route-planner/
  index.html
  src/engine.js      씨앗·묶기·순서·시간·자르기 (DOM 없음)
  src/travel.js      거리 → 분 (DOM 없음)
  src/state.js       URL 해시 ↔ 상태 (DOM 없음)
  src/ui.js          단계·지도·패널
  data/london.json   data/paris.json
  tests/engine.test.js  tests/state.test.js
  scripts/validate-data.js
```

바닐라 JS, 빌드 없음, GitHub Pages가 그대로 서빙. 외부 의존은 Leaflet 하나(CDN, 버전 고정).

## 4. 검증

| 대상 | 어떻게 | 통과 기준 |
|---|---|---|
| 엔진 | `node tests/engine.test.js`, 런던 20곳·3일 픽스처 | 꼭 가기 전부 포함 · 어느 날도 `dayEnd` 초과 없음 · 뺀 것이 최하 weight · 두 번 돌려 동일 · 하루 순서가 완전탐색 최소와 일치(≤7곳) |
| 엔진 극단 | 같은 파일 | 1곳 · 전부 꼭 가기 · 용량 3배 초과 · M > 장소 수 |
| 이동 추정 | 같은 파일 | 알려진 쌍 5개(세인트폴→버러 25±8 등)와 비교 |
| 해시 | `node tests/state.test.js` | encode → decode 왕복 동일, 깨진 해시 → 기본값 |
| 데이터 | `node scripts/validate-data.js` | 필수 필드 · 좌표가 도시 bbox 안 · `opts` 1개↑ · `id` 고유 |
| 화면 | 손으로 1회 | 폰 폭·데스크탑, Leaflet 로드, 링크 복사 후 새 탭에서 복원 |
